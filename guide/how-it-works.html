How it works ​

Tackora is a Kanban board for coding agents. Every ticket is one session of a coding agent: Claude Code or the DeepSeek Harness (dsh), the real CLI running in a terminal inside the ticket. You pick the agent when you start a ticket, or set a default under When a ticket starts in Settings. The board shows what each agent is doing, and moves the cards as the work progresses.

This page describes the design. What's built so far is in Status.

The board ​

Tickets are cards in five columns: Open, In progress, Needs review, Changes requested and Resolved. Closed tickets are hidden. The same tickets are also a filterable list, and a journal of what happened each day.

Each card has two pieces of information:

  • Its column: where the work stands.
  • Its agent badge: what the agent is doing right now.
BadgeMeaning
RunningThe agent is working on your last prompt.
DoneThe agent finished its turn and is idle at its prompt. Reply whenever you like.
Needs permissionThe agent is blocked, asking to run a command or edit a file. This is the only state that counts as "needs you".
Not runningNo terminal is open. Opening the ticket starts it again: a Claude session resumes, a dsh ticket runs afresh.

When an agent is Done or Needs permission while Tackora is in the background, you get a desktop notification.

The sidebar's Active list shows every ticket whose agent is working or waiting, with the ones that need you first, so you can jump between agents without going back to the board. Pin any ticket (the pin button next to its title) to keep it under Pinned.

New to Tackora? A Getting started checklist above the board walks you through adding a project, creating and starting a ticket, and trying Ctrl+K. Each step ticks itself off as you do it.

Cards move on their own ​

WhenThe card moves to
You send the agent its first promptIn progress
You submit for review and the pull request opensNeeds review
A reviewer requests changes on the pull requestChanges requested
The agent starts working on those changesIn progress
The pull request is merged, in Tackora or on GitHubResolved (the worktree is removed)
You commit with Finish ticked (direct mode)Resolved

You can always drag a card yourself. Dragging to Needs review submits it for review, and dragging to Resolved merges it (Tackora asks first). Other moves just change the column.

Tickets are sessions ​

Starting a ticket starts its agent session, and Tackora ties it to the ticket. A Claude session gets the ID Tackora chooses before Claude starts (claude --session-id <id>), so reopening the ticket later, even after restarting Tackora, resumes that same session with its full history (claude --resume <id>).

A dsh ticket is different. It runs dsh --profile acp behind Tackora's helper, but dsh names the session itself in its reply and has no way to resume one. The helper keeps one conversation on one session for as long as the terminal stays open, so you can reply to it like any other ticket — but closing the terminal ends that conversation. Reopening the ticket runs a fresh session whose task is the ticket's context (what the ticket is, and its notes), not the earlier conversation.

When you start a ticket you choose the agent, the model, the effort level and the permission mode. Defaults come from settings, and When a ticket starts in Settings can skip the dialog and start on one agent's defaults instead. For a Claude ticket you can change them inside Claude afterwards; the ticket shows what's actually in use. Start over begins a new session and keeps the old one's agent time in the ticket's history.

Have a quick question that isn't really a task? Create a quick ticket with just a prompt.

What differs for a dsh run ​

  • No resuming a closed terminal. dsh names its own session and can't reopen one, so the ticket's button reads Run again: it starts a fresh task from the ticket's context.
  • Its own model route. dsh resolves models through its own provider route (deepseek-official), not a Claude plan: deepseek-v4-flash, deepseek-v4-pro and deepseek-v4-flash-vision-exp. Tackora pins the model you pick for the session.
  • No permission modes yet. Claude's permission modes have no dsh equivalent Tackora can set, so a dsh ticket runs with the harness profile's own permissions and never shows the Needs permission badge. Settings shows Model only for dsh, and the start dialog hides Permissions.
  • No effort level. Tackora sends dsh a fixed reasoning effort suited to a ticket's scoped, already-planned work.
  • Its state comes from its own log. dsh has no hooks and no status line, so Tackora reads the run's session log for the Running and Done badges and for its progress lines.

Direct or worktree ​

Each ticket runs in one of two ways. Direct is the default, and each project can set its own default.

Direct (default)Worktree
Where the agent worksThe project folder, on whatever branch is checked out (e.g. main)A separate folder with a new branch for this ticket
Several tickets on one project at onceOne running at a time, so two agents don't edit the same filesYes
When you're doneCommit, optionally push, and tick Finish to resolveSubmit for review opens a pull request. Merging it resolves the ticket.

Worktree branches are named from the ticket, like fix/login-throttle or feat/export-csv. You can edit the name and the base branch when you create the ticket.

Ask Tackora ​

Press Ctrl+K and type what you want in plain words:

  • "Clone anas1412/api and add it as a project"
  • "Add a ticket to web: the signup button does nothing on Safari"
  • "What's waiting for me?"
  • "Move all the docs tickets in api to Closed"

Tackora doesn't have its own AI. It gives Claude Code a set of Tackora tools: list and create projects and tickets, edit them, move cards, start sessions. The agent then does what you asked and replies under the command bar, and the cards it changed are highlighted. Press Continue to follow up.

Agents working on tickets get the same tools, whichever agent runs them. In any ticket's terminal you can say "add a follow-up ticket for the signup form", and an agent can file a ticket itself when it spots another problem. Every change records who made it (you, the command bar, or the agent on ticket #7).

Anything destructive or that touches Git waits for you: deleting, removing a project, submitting for review, merging, or changing more than five tickets at once. Tackora shows what's being asked and who's asking, and nothing happens until you click Allow.

Agents ​

When Tackora starts, it checks which coding agents are installed and ready: claude on your PATH and signed in, and dsh on your PATH (it takes its credentials from the environment). If neither is ready, it shows a setup screen with each agent's install or sign-in command and a Check again button, and nothing else. Claude Code is only needed for Claude tickets: a dsh ticket needs no Claude install and no Claude plan.

Usage ​

Tackora shows what the agents and Claude itself report, and doesn't estimate money. Plan limits are Claude's:

  • Plan limits (Claude tickets): your 5-hour and 7-day usage and when each resets, in the top bar, for the Claude Pro, Max, Team or Enterprise plan you're signed in with. The usage popover also shows the account, organization and plan.
  • Per ticket: the agent's state, and the tokens in the session's context, the lines it changed and the time it spent working. Claude reports these through its hooks and status line. A dsh ticket has neither, so its state comes from its own session log and its changed lines from git; the harness reports no tokens and no working time.
  • Usage page: agent time and lines changed per day, project, model and ticket.
