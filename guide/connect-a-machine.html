Connect a machine ​

Agents run on your own machines, never on ours. A machine you connect is called a runner.

The machine needs Node.js (for npx), your repositories cloned, and at least one coding agent installed and signed in: Claude Code, Codex, OpenCode or Gemini CLI. The runner finds them by itself, and each ticket can pick any agent its machine has.

Steps ​

  1. Open a terminal, in any folder (your home folder is fine), and run:

    bash
    npx tackora@latest start

    It prints a link and an 8-character code.

  2. Open the link (or go to Runners and type the code). Check the code is the one your terminal shows, then press Connect.

  3. The terminal says Tackora is running in the background and gives you the prompt back. The runner keeps going, starts again when you log in, and shows up on the Runners page.

  4. In each repository's folder, run:

    bash
    npx tackora@latest add

    The runner picks it up within 15 seconds and works on that repository's tickets.

npx tackora@latest remove in a folder stops working on that repository (its files stay as they are). npx tackora@latest stop takes the machine offline until you run start again.

On Linux the runner is a systemd user service, on macOS a launchd agent, on Windows a task that starts at logon. Its output is in ~/.tackora/runner.log (npx tackora@latest logs). It takes the API keys of the shell you ran start in (for example ANTHROPIC_API_KEY): after changing one, run start again.

All commands ​

CommandWhat it does
startConnect this machine (the first time), then run in the background, starting again at login. It updates itself within an hour of a new version, once no ticket is running.
add [folder]Work on a repository: the folder you're in, or the one you name.
remove [folder]Stop working on a repository. Its folder stays as it is.
statusWhether it's running, its repositories and the agents it found.
logsWhat the background runner printed. logs -f keeps following it.
stopStop the background runner: the machine goes offline until start runs again.
start --foregroundRun in the terminal instead, for servers, containers or debugging. Ctrl+C stops it and its agents.
--versionWhich runner version this is.
